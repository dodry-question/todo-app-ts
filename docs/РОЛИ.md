# Кто и что делает — чёткий список ролей

Короткий справочник для всей команды: у каждого своя зона, свои файлы и свой порядок действий.
Подробности задач — в `docs/plan.md`, контракт с бэком — в `docs/api.md`.

## Участник 1 — фронт: каркас и авторизация

**Делаешь:**
- каркас приложения и маршруты `/login`, `/register`, `/`
- все запросы к API через `api.ts` (`/api/auth/*`, `/api/tasks/*`)
- хранение токена и восстановление сессии после перезагрузки (`auth.tsx`)
- защита страниц: без токена — только вход/регистрация
- страница входа (email, пароль, ссылка на регистрацию, ошибки)
- страница регистрации (имя, email, пароль, подтверждение пароля, ошибки)
- кнопка «Выйти»
- сверка `types.ts` с `docs/api.md` (названия полей должны совпадать)

**Не правишь:** папку `backend/`, `docs/api.md`, `TasksPage.tsx`/`components/*`/`styles.css`, Docker-файлы.

## Участник 2 (Илларион) — бэк: сборка, база, задачи

**Делаешь:**
- проект собирается и запускается (`build.gradle.kts`, Gradle)
- подключение к PostgreSQL, создание таблиц
- модель, репозиторий, сервис и маршруты задач (`/api/tasks/*`)

**Не правишь:** файлы авторизации (User, JwtConfig, AuthService, AuthRoutes — их делает Миша), папку `frontend/`, `docs/`, `docker-compose.yml`.

## Миша — авторизация, контракт API, проверка сценариев

**Делаешь (и это первое дело команды):**
- заполняешь `docs/api.md`: поля запросов/ответов, единый формат ошибок, как передаётся токен — до того, как фронт пишет код
- регистрация (имя необязательно, email, пароль; занятый email — понятная ошибка; пароль не в открытом виде)
- вход (проверка пары email/пароль + выдача токена) и выход
- эндпоинты `/api/auth/register`, `/api/auth/login`, `/api/auth/logout`
- прогон всех сценариев (Postman/браузер): своя задача / чужая / без токена
- тестовые данные: 2 пользователя, по 3 задачи каждому

**Не правишь:** фронт, Docker-файлы, задачи бэка (их делает участник 2).

## Участник 5 (Рувим) — Docker и PostgreSQL

**Делаешь:**
- `docker-compose.yml`: три сервиса — фронт, бэк, база (больше ничего)
- том для данных (после перезапуска данные остаются)
- `Dockerfile`-ы, `nginx.conf`, `.dockerignore` для обоих
- `.env.example` (в git идёт только он, `.env` — нет)
- `README.md`: скопировать `.env.example` → `.env`, что поменять, запуск одной командой, адреса, логи
- проверка на чистой машине: склонировал → `.env` → `docker compose up` → работает

**Не правишь:** код фронта и бэка, `docs/`. Если образ не собирается — зовёшь владельца кода.

## Порядок работы всей команды

1. **Договор API.** Миша заполняет `docs/api.md`, участники 1 и 4 подтверждают. Без этого код не пишем.
2. **Код параллельно.** Фронт (1 и 4) и бэк (2 и Миша) — одновременно.
3. **Docker.** Рувим собирает всё в один `docker compose up`.
4. **Проверка.** Общий чек-лист в конце `docs/plan.md` — пока не пройдёт, не сдаём.

## Правила репозитория

1. Работаешь в своей ветке, в `main` — только через pull request.
2. Файлы из чужой зоны не правишь — пишешь владельцу файла.
3. `.env`, пароли, токены и ключи в репозиторий не попадают.
4. Перед пушем — `git pull`, чтобы не перетереть чужое.
5. Не получилось — пишешь в общий чат, не сидишь молча.

## Если нужно чужое изменение

Смотри сводную таблицу вверху: нашёл нужный файл → нашёл его владельца → написал ему. Сам не правишь.
